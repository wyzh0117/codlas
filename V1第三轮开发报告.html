一、本轮范围

上一轮的记录把话说清楚了两件事：桌面壳不存在（V1-E 是 ⏳），以及 §14 第 7 项"用户点击某个 Issue"缺手势不缺逻辑。 本轮把这两件做完，并且在做的过程中让 ADR-030 的第二种后果现形—— 它不是壳自己的毛病，是事件链上的缓存在另一条读路径上等着。

本轮三条硬约束。 ① 壳只能显示引擎算出来的东西，唯一的写是 §7.4 的确认（禁止 4 / 禁止 7）； ② 补屏幕不等于补能力——三块新屏幕都是既有端口的薄展示，不新增事件类型（禁止 8）； ③ 没输入就拒绝，不替用户猜出一份空包（§62 Degradation）。

二、桌面壳：apps/desktop（Tauri 2）

十二个命令里十一个是只读视图，唯一的写是 apply_pending，它逐条走 accept_change_proposal / Inbox 判定。 数据库路径与当前项目都由 vibe_cli::app::App（CLI 自己的 runtime）给出，所以窗口和终端不可能各挑一套项目状态。

三、§14 第 7 项：那只手，以及"引用就是意图"

  • 交互。偏航屏每条提示、检索屏每一行都带一个「带它去上下文 →」；上下文屏多出一个 kind:id 聚焦框， 点击会自动填进去并立刻编译一版。包自己会说聚焦在哪一条（ContextView.focus），不会让一版聚焦包长得像通用包。
  • 点了就不需要再写问话。引用本身就是意图：壳按 CLI 完全相同的方式把它写成 context for issue:I-1， 并把那条记录放到 §42 阶梯的第 1 层（priority 1、必带上）。
  • 不另写第二套引用语法。vibe_cli::context::parse_ref 从 CLI 私有改为 pub，桌面壳直接复用； 少了 kind 的引用（I-1）与"既没问话也没点选"都是拒绝，不是一份能过预算的空包。
  • 测试。a_click_on_a_record_focuses_the_pack_without_a_sentence（views.rs） 与 a_selected_record_travels_at_the_top_of_the_ladder（cli_e2e.rs）分别钉住壳与 CLI 两扇门。

四、顺带修掉的缺陷

ADR-030 的第二种后果：§42.1 的"用户显式选择"经物化出来的实体行解析。 retrieve.rs 的 selected() 走 repos.entities.get(kind, id)，而那些行是折叠的缓存。 于是：刚 wp event 追加一条 Issue、还没跑过 wp map 时，wp context plan --select issue:I-1 答的是 not found in this project——缺陷在桌面壳的测试里第一次暴露（12 条测试跑到第 12 条时红了）。
  • 修法不是再造一条读路径。编译包之前显式调用一次 Reducer::project_state 写穿缓存： CLI 的 context dispatch、wp-mcp 的 context_pack、桌面壳的 context_view 各一行。 wp map（ProjectMapCompiler::compile）与快照本来就是同一个动作，所以这不是第二套状态（禁止 4）。
  • 覆盖补齐。--select 此前只有引擎层测试（pack_order.rs），CLI 的 flag → request 那条线没人守；本轮补上。
  • 顺手记下的构建事实（都在 ADR-029 的 build notes 里）：tauri::generate_context! 要求 icons/icon.png 是真 RGBA PNG（调色板 PNG 直接编译失败）；camelCase 的 JS 参数对应 snake_case 的 Rust 形参（maxTokens → max_tokens）。
  • 清理。删掉临时目录 vibe_images/（生成图标时的中间产物，未被任何文件引用；apps/desktop/icons/icon.png 才是真正被打包的那一张）。

边界自检（§19 禁止 1–10）

  • 禁止 1 团队/企业功能：未引入。
  • 禁止 2 普通 Todo/Kanban：总览屏是折叠结果的计数，不是待办列表，且明写"要看某一条去时间线或项目地图"。
  • 禁止 3 / 4 / 5 / 6：壳不建第二套状态、不 detach 决策于 Charter/Context、不重写 Charter、提案不经确认不成事实。
  • 禁止 7：模型不参与这些屏的编译。
  • 禁止 8：本轮三块新屏幕全部是既有端口的展示层；AEP 屏显示 dormant 而不是在建工程。
  • 禁止 9：聊天记录没有出现在任何一屏的事实来源里。
  • 禁止 10：本轮改动全部挂在 §21（八屏）、§14 第 7 项、§61 V1-E 与 §62 上，关系写在 ADR-029 / ADR-030 的修订里。

三、真 Chrome 与 TCC：一条静默卡死的根因（ADR-035）

扩展装入后第一次跑 native host，Chrome 侧永远等不到回答——进程没报错、没日志、 连一行 stderr 都没有。用 sample 抓了 Chrome 拉起的那个进程，样本 100% 停在 dyld 的 open()：macOS TCC 在 main() 之前就把 ~/Documents 下的二进制拦下了，Chrome 拉起的进程连第一行代码都没跑到。

  • 根因不是权限没给，是位置：native host 二进制不该住在 ~/Documents | Desktop | Downloads——TCC 的守卫目录按路径拦进程，不问签名；
  • 修法：宿主装到守卫目录之外（本轮移到 ~/codlas-demo/host/bin/），一次即通；
  • 补防：wp host manifest 现在会检测并警告（guarded_folder()）， 测试 guarded_folders_are_recognised_by_path_component_not_text_prefix 把"按路径分量识别、 不按文本前缀"钉死（否则 ~/Documents-archive 这类会误伤）；
  • 决定全文：ADR-035—— 只警告不拒绝，因为正确位置因机器而异，且拒绝会把"能用但不在推荐位置"的合法安装也打死。

四、真会话进链路：normalizer 会吞掉对话（ADR-034）

拿本项目自己的 CLI 会话（26 MB JSONL，215 轮）做真材料。第一遍导入只进来 22/215 轮—— 少的不是边角，是所有 assistant 的回答。查下去是 normalizer 把消息里的 content 块当成了一段平文：thinking、tool_use、tool_result、 image 这些机器块被拍平进"发言"，而真正的 type:"text" 块反而被吞。

修复前 / 后数字
修复前22 / 215 轮（丢弃全部助手文本）
修复后215 / 215 轮（35 user + 180 assistant），导入 215 messages / 51 events / 47 pending
幂等复检第二遍导入 0 新增（drain 身份而非时间戳，§51）
事件闭环接受其中一条 claim → seq 37→66，tasks 2→3
新增测试crates/ingestion/tests/normalizer.rs ×2： jsonl_reads_text_blocks_and_skips_thinking_and_tool_blocks / a_block_without_a_type_but_with_text_is_still_text
为什么值得一条 ADR：这不是解析口味问题，是禁止 9 的边界—— 机器块被拍平成"发言"就是把机械动作伪装成人的话语，把工具往返当成人的观点。 ADR-034：只读 type:"text"， thinking / tool_use / tool_result / image 一律跳过、绝不拍平；无 type 但有 text 的块仍算文本。

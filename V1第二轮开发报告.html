一、本轮范围与结论

第一轮把 §7.2 那条链跑通了：Source → Event → Reducer → Project State → PROJECT_MAP → Context Pack → Agent。 本轮不扩展产品概念（§19 禁止 8），只把开发文档里留下缺口或做了一半的八项做完，并把每一项都落到可运行的 CLI 命令、端口或 crate 上，配上能失败的测试：

  • §17 / §45 证据读取入口 wp evidence
  • §55 备份侧 + §62 Recovery：wp backup create|status|verify|restore
  • Stage H Adapter Health + wp adapters
  • §39 监听事件 + wp watch
  • §59 / §60 性能与成本预算（Stage H Performance）
  • §52 L3 近似重复：只提示，不删除 + wp duplicates
  • §58 Adapter Contract 补齐 inject / fallback 与契约测试
  • §38.5 MCP 基础接口：新 crate crates/mcp-server + wp-mcp 二进制
一句话结论：V1 的核心、采集、上下文、防偏航与加固五项现在都有可读、可测、可恢复的表面； 还缺的只有界面本身——V1-E 的 Tauri 桌面壳与 V1-D 的浏览器扩展 + Native Messaging。 这两项按 ADR-016 仍然是有意推迟，而不是遗漏。

三、顺带修掉的三个真缺陷

都不是为了让学生代码通过而放宽断言，而是测试先失败、根因在实现里：

  • 读取窗口不确定。recent_messages 只按 observed_at DESC 排序，而批量导入给每一行盖的是同一个时间戳—— 于是同一个库两次扫描可能给出不同的近似重复提示。补 rowid DESC（store 分配、单调）作为 tie-break。 这动摇的是 §7.2 的确定性重放承诺，不只是界面观感。
    crates/storage/src/conversation.rs
  • 事件日志方向反了。store 为了 LIMIT 取的是"最近若干条"并以 seq DESC 返回； MCP 的 project_timeline 承诺"oldest first"，所以截断保留、方向翻转。测试断言四条事件的类型序列与游标窗口内容后才暴露它。
    crates/mcp-server/src/tools.rs
  • 契约测试差点自证成功。带默认方法体的 trait 让一个"什么都不做"的 adapter 也能通过七动词检查。 加了负控 fixture（声称 PREPARE_PAYLOAD 却交不出 payload）之后，review 才被证明会点名。
    crates/ingestion/tests/contract.rs

  • ADR-027 — 预算优先是工作量；§60 由依赖声明钉死。

六、边界自检（对着 §19 的禁止项）

禁止项本轮怎么守的
禁止 4 · 不维护两套 Project StateMCP 六个工具全部调 CLI 已在用的 service；预算测试断言物化行等于纯折叠结果；备份是数据库副本而非第二份事实；近似重复不写入。
禁止 7 · 核心不直接依赖 SQLite / 具体 Agentrusqlite 仍只出现在 crates/storage——本轮把这条变成 cargo test 的一部分（manifest 扫描）。wp-mcp 只经端口读。
禁止 8 · 不为未触发功能提前实现inject 只有契约与默认实现，写入侧仅由测试 fixture 触发；没有守护进程、没有 MCP prompts/resources/sampling；Keychain 依旧 opt-in。
禁止 9 · 聊天记录不是最终项目记忆监听信号与近似重复都不进状态；提示只做人判断的输入。
§53 / §54 安全context_pack 无论来自终端还是管道都过 Policy Filter 并留 audit；备份文件里只有 secret_ref，秘密值按 ADR-017 在库外。
§29 判断权在人工具名禁止出现 confirm / set_ / create / delete / resolve / append，由测试守住；MCP 表面没有任何写动词。

七、仍然没做（如实列出）

  • V1-E Tauri 桌面壳：apps/desktop 仍不存在。本轮反而多备了三块原料——wp adapters 的判词、wp duplicates 的提示、wp backup status 的完整性结论。
  • V1-D 浏览器扩展 + Native Messaging：没做。这也是 open / inject 第一次被真实实现的时刻。
  • wp watch 是手动 pass，不是常驻监听；没有 notify、没有定时器。
  • §52 L3 是词法近似，语义版在 AEP-002；中文检索的分词盲区仍在（等 trigram 或 AEP-002）。
  • §58 的写入侧对所有内置 adapter 返回 None；发送依然是人的动作（§7.8）。
  • 第一轮遗留：feature_creep 规则在大仓库上会刷屏，等界面聚合。
